# Trip suggestion agent

## Stage 1: suggestion, not booking

The first release turns a traveller profile into a structured itinerary idea grounded in the current Way to Asia journey catalogue. It runs through `POST /api/trip-suggestion` using the Cloudflare Workers AI binding named `AI`.

The response contract deliberately separates:

- editorial suggestions generated by the model;
- catalogue journeys resolved by the server from valid slugs;
- supplier availability, which is always `not-connected` in stage 1;
- pricing, which is always `illustrative-only` in stage 1.

The model never supplies trusted links or prices. The server resolves those from local catalogue data after validating the structured output.

## Cloudflare setup

Add a Workers AI binding named `AI` to both Preview and Production for the matching `waytoasia` Pages project, then redeploy. For local Pages development use:

```sh
npx wrangler pages dev dist --ai AI
```

Workers AI usage is billable in local development as well as production.

## Supplier-ready next stages

The provider-neutral search contract now lives in `src/lib/suppliers/`. The researched provider sequence and commercial questions are documented in `docs/supplier-integration-options.md`.

1. Use the active HBX evaluation account for read-only sandbox testing of Hotels, Activities and Transfers. Do not start certification, commercial onboarding or live booking.
2. Add anonymous session state so travellers can refine the same proposal over several turns.
3. Implement the provider-neutral read-only adapter against local fixtures first, then validate it against HBX evaluation endpoints after the agent has exact dates, room allocation, child ages, traveller country, currency and locations. Keep credentials and raw responses server-side.
4. Add human approval and a saved proposal before any hold, reservation or payment action.
5. Add supplier-specific booking adapters only after cancellation terms, currency handling, markups, audit logs and failure recovery are defined.

No supplier should be connected directly from the browser. Live results must identify the provider, retrieval time, currency, inclusions and cancellation conditions.
